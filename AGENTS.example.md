# Правила переносимой сборки Pi

- Исходники этой сборки находятся в {{SOURCE_ROOT}}. Не путай их с cwd разрабатываемого проекта.
- Наши общие скиллы: skills/<slug>/SKILL.md, name <slug>, вызов /pi:<slug>. Категория определяется расположением, не префиксом.
- Наши рабочие скиллы: work/skills/<slug>/SKILL.md, name <slug>, вызов /work:<slug>. Существующие имена с -oneab сохраняй.
- У Pi единое пространство нативных имён. Проверяй конфликты с подключёнными скиллами; не добавляй префиксы автоматически.
- Каждый extension — атомарная папка extensions/<slug>/ с index.ts; рабочий — work/extensions/<slug>/. Helper-файлы храни внутри своей папки. Не импортируй код из соседних extensions или общей lib/. Для создания используй scripts/components.mjs или согласованную ручную правку.
- Явные create / «общий» означают общий слой; create work / «рабочий» означают work. Без явного режима определяй по обязательным зависимостям; при неоднозначности спрашивай. Противоречие между явным режимом и зависимостями уточняй, не меняй категорию молча.
- Сторонние ресурсы относятся к /other:<name>. Не редактируй управляемые PAIW-источники и не переноси их в эту сборку.
- До создания скилла используй правила /pi:skill-creator. Для перевода в рабочий слой доступны /pi:to-work и предварительный просмотр scripts/components.mjs to-work.
- Не добавляй каждому компоненту отдельные записи в .gitignore, manifest или namespace-extension: они используют каталоги и обнаружение ресурсов.
- Общие компоненты не должны содержать credentials, внутренние адреса, жёсткие пути пользователя или обязательные рабочие зависимости.
- После изменения выполняй node scripts/check-portability.mjs и доступные проверки затронутого кода. Папки tests/ и work/tests/ этой сборки не создавай без запроса пользователя. Предлагай /reload. Не коммить и не публикуй автоматически.
- Новая зависимость npm-extension добавляется в config/settings.base.json с точной версией. Runtime-зависимости своего extension объявляй в его локальном package.json и согласуй их установку; host-пакеты Pi остаются peerDependencies.
- Gitignore не является защитой от уже опубликованных секретов. Перед публикацией проверяй конкретный состав коммита и права на сторонний код.
