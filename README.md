# pi-setup

Переносимая сборка Pi. Нужен Node.js ≥22.19. Одна команда устанавливает или обновляет сборку и запускает Pi:

## Установка и обновление

```sh
npx --yes --package="https://codeload.github.com/GeorgeTyupin/pi-setup/tar.gz/refs/heads/main?v=0.2.1" pi-setup
```

После push изменений в `main` эта же команда подтянет их на другом компьютере. Общий профиль загружает актуальный SHA, рабочий — обновляет чистый локальный checkout через `git pull --ff-only`, не перенося `work/`. Незакоммиченные или не отправленные изменения не распространяются. Подробности и ограничения — в [сопровождении](docs/pi-maintaining.md#обновление-на-другом-компьютере).

## Разработка и сопровождение

- [Pi development](docs/pi-development.md): написание скиллов, extensions и агентов, соразмерные проверки, короткие отчёты в чат.
- [Pi maintaining](docs/pi-maintaining.md): выбор общего/рабочего слоя до создания, подключение, аудит и обновление.
- [Публикация](docs/publishing.md): проверка состава, секретов и прав на сторонний код.

## Подключение наших скиллов

Вспомогательный скилл может подключаться по контексту уже разрешённой задачи, если в его `SKILL.md` задано `disable-model-invocation: false`. При `true` сохраняется явный вход. Выбирай по актуальному описанию и условиям применения, без фиксированного списка помощников. Это выбор инструкций, а не разрешение начать новые правки, другой flow, запуск агентов или инфраструктуры. Расширение учитывает эту политику только для наших скиллов; внешние и Generic/PAIW-скиллы и их прежний режим не меняются.

## Flow проверок

`/pi:verify` координирует выбранные ревью, тесты и локальные HTTP-проверки. `/pi:code-review`, `/pi:tester`, `/pi:curler` работают и отдельно. Ревью выбирается и по обычной просьбе, без команды. Явные параметры из текста или флагов используются сразу; через `ask` уточняется только недостающее. Рекомендуются агенты у verify и основная сессия у отдельных проверок. Effort нужен только для code-review, в обоих режимах.

```text
/pi:verify
/pi:verify --agent --checks review,tests,curl --effort high
/pi:verify --inline --checks review --effort medium
/pi:code-review --agent --effort high
/pi:tester --agent
/pi:curler --inline
```

Ревьюер получает **fork**, тестировщик и curler — **fresh** с коротким заданием. Проверяющие не исправляют код. Правила остаются в исходных скиллах, профили агентов их не копируют. Оркестрация не создаёт ветки, коммиты или MR.

Результаты агентов возвращаются кратким текстом прямо в чат: статус, существенные находки/ошибка и ограничения. Файлы отчётов и ссылки вместо итогов по умолчанию не используются; служебные сессии и приватные логи раннера могут сохраняться отдельно.

JWT и другие credentials передаются только ссылками на файлы, не моделью. Необязательный PAIW-указатель и защита HTTP описаны в [verification-runtime](extensions/verification-runtime/README.md); единые правила режимов — в [контракте исполнения](skills/verify/references/execution.md). Нужны Pi 1.4.0, установленный curl и `/reload` после обновления ресурсов.
