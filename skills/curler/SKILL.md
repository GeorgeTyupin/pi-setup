# Проверка HTTP-ручек

Работай только по прямой просьбе проверить ручки или по явному вызову этого скилла. Только локальное окружение, без субагентов и дочерних CLI.

## Сценарии

1. Возьми из диалога методы, пути, ожидаемое поведение и ограничения. Если списка нет, прицельно прочитай diff контракта и обработчиков. Не считай неизменённую спеку доказательством отсутствия внешних изменений: тело ответа или валидация могли измениться в другом слое.
2. Назови сценарии и адрес приложения. Только localhost, 127.0.0.1 или ::1. Не переходи по HTTP-редиректам на внешние адреса. Прод, стейдж и внешние системы не проверяй.
3. Прямая просьба покурлить разрешает согласованные локальные HTTP-запросы. Если запрос меняет данные, сначала опиши последствия и получи явное разрешение на мутацию, если его ещё не было.

## Окружение и данные

- Используй уже известные контейнеры, порты и способы аутентификации. Не проводи разведку заново без причины.
- Недостающие сведения бери из Makefile, docker-compose, безопасных шаблонов конфигурации и кода. Не угадывай названия контейнеров и базы.
- Подъём окружения, миграции, подготовка или удаление данных требуют отдельного разрешения. Не меняй среду автоматически.
- Не читай секретные конфиги и .env для разведки. При отсутствии безопасного способа аутентификации попроси пользователя подготовить TOKEN или TOKEN_FILE. Не запрашивай значение секрета в чате.
- Секреты используй только из переменных окружения или защищённых временных файлов вне репозитория. Не печатай токены, пароли, куки и заголовки Authorization. Не используй curl -v или shell tracing, способные вывести их.

## Выполнение

- Выполни только выбранные сценарии. Используй timeout и отдельно фиксируй HTTP-статус и транспортные ошибки.
- Независимые чтения можно запускать параллельно. Изменяющие запросы упорядочивай по зависимостям.
- Не исправляй код, не меняй Git, не вызывай другие скиллы автоматически.
- Не представляй невыполненный запрос как проверенный. Если окружение недоступно, сообщи причину и дай подготовленную команду с пометкой "не выполнено".

## Отчёт по запросу

### METHOD /path
- Сценарий и ожидаемый результат.
- Тело запроса без секретов.
- HTTP-статус и существенная часть фактического ответа, с редактированием секретов.
- Вывод: совпало с ожиданием или нет и почему.
- Команда для повтора, с $TOKEN или $TOKEN_FILE вместо секретов.

Отдельно укажи разрешённые изменения локальных данных, ограничения проверки и при необходимости шаги Postman. Итог относится только к выполненным запросам. Пиши по-русски, коротко, без эмодзи.
