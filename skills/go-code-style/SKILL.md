# Стиль Go-кода

Пиши максимально простой и понятный код в рамках задачи.
Необходимую сложность сохраняй и делай явной: простота не должна
достигаться ценой корректности, надёжности или важных проверок.

## Приоритет стиля проекта

Стиль проекта первостепенен. Опирайся на его инструкции,
договорённости и существующий код, затем — на общие идиомы Go.

## Переменные

Инлайни лишние переменные. Если значение используется один раз,
предпочитай непосредственное выражение. Оставляй переменную, когда
её имя объясняет смысл или заметно улучшает читаемость.

## Сценарии, функции и методы

- **Сохраняй сценарий цельным.** Не выделяй функции только ради разделения
  кода. Выделение оправдано переиспользованием, уже известным повторным
  сценарием, самостоятельной существенной логикой или сложностью метода.
  Фиксированного ограничения на число строк нет.
- **Fallback можно выделять отдельно**, если это упрощает основной сценарий
  и сохраняет понятным запасной путь, даже при одном месте вызова.
- **Уменьшай вложенность.** Предпочитай ранние возвраты, когда они делают
  основной ход выполнения понятнее.

## Форматирование

Разделяй логические блоки пустыми строками. Операцию и следующую
за ней проверку ошибки держи вместе. Связанные действия не разрывай
механически; новую самостоятельную часть отделяй. Используй gofmt.

```go
record, err := queries.GetCall(ctx, id)
if err != nil {
	return model.Call{}, fmt.Errorf("не удалось получить звонок: %w", err)
}

return adapter.CallFromRecord(record)
```

## Границы изменений

Применяй правила прежде всего к новому коду. Существующую кодовую
базу специально под них не переделывай. Редкие точечные исправления
допустимы для согласованности с новым кодом или устранения явного
нарушения идиом Go. Не расширяй задачу сопутствующим рефакторингом
и не меняй контракты или поведение вне её объёма.
