# Перенос компонента в рабочий слой

Корень сборки определяется по местоположению этого SKILL.md: два каталога вверх, не cwd проекта. Прочитай scripts/components.mjs и README.md этой сборки.

1. Определи тип и точное имя. Подходит только наш компонент из skills/ (кроме управляемого skills/paiw/) или extensions/. Управляемые PAIW-источники и сторонние пакеты не перемещай.
2. Выполни читающий предварительный просмотр: node scripts/components.mjs to-work <skill|extension> <имя>.
3. Покажи исходный и целевой пути, обнаруженные ссылки и зависимости. Если нужны отдельные правки импортов или общей логики, сначала согласуй их план. Не переносишь общую зависимость вместе с компонентом молча.
4. Получи явное подтверждение переноса. Сам вызов скилла не отменяет эту проверку.
5. Выполни ту же команду с --apply. Она отказывается затирать существующий компонент, следовать симлинкам или переносить компонент с неразобранными ссылками. Исправление зависимостей выполняй только в согласованной области.
6. В рабочем профиле каталог уже подключён. В домашнем профиле не подключай work автоматически: объясни, что для него требуется локальная рабочая конфигурация.
7. Проверь node scripts/check-portability.mjs. Предложи /reload; алиас изменится с /pi:<slug> на /work:<slug>, внутреннее имя сохраняется.

Весь work/ исключён из Git. Не меняй .gitignore и manifest для каждого компонента, не коммить, не пушь и не удаляй историю. Если компонент ранее был опубликован, перенос не убирает старое содержимое из истории Git; сообщи об этом отдельно.

Обратный перенос в общий слой автоматически не выполняй: требуется проверка зависимостей и переносимости.
