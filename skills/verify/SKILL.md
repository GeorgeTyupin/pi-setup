# Verify

Координатор проверок в основной сессии, **не отдельный агент** и не Generic Flow разработки.

1. Прочитай [общий контракт исполнения](references/execution.md). Вызови `verification_options` для `verify`, передав исходные аргументы. Получи через `ask_user_question` только недостающие проверки, режим и effort ревью; рекомендуй агенты, но не запускай их без выбора. Если все параметры заданы флагами, вопросов об этих параметрах нет.
2. Установи точную область и вводные. Для выбранных проверок подготовь соответствующие задания; отсутствующие сведения/разрешения уточни до их исполнения. Ненужный curl или тесты не добавляй автоматически. При неизвестном наборе проверок спроси, не считай обязательными все три.
3. Используй правила только из исходных скиллов: [code-review](../code-review/SKILL.md), [tester](../tester/SKILL.md), [curler](../curler/SKILL.md). Не копируй их алгоритмы сюда и не читай невыбранные скиллы без причины.
4. В режиме `agent` запусти выбранных исполнителей отдельными фоновыми вызовами `subagent`: **code-reviewer — fork, tester и curler — fresh**. Effort передаётся только ревьюеру. Не запускай verify внутри ребёнка. Режим/effort уже выбраны — дети их повторно не спрашивают.
5. Независимые проверки запускай параллельно. При общем изменяемом окружении упорядочь тесты и HTTP-сценарии или запроси изоляцию; не поднимай инфраструктуру молча. Сохрани исходное состояние проверяемых файлов для проверки актуальности результатов.
6. В `inline` выполни исполнительские части выбранных скиллов сам. Effort временно переключается только на время code-review и затем восстанавливается; tester/curler его не меняют.
7. Для async-запусков освободи чат и дождись native-уведомлений, не опрашивая их в цикле. По завершении сопоставь результаты с текущим состоянием области. Верни прямо в чат краткую сводку по каждой проверке: статус, существенные находки/ошибки, `stale` и что не удалось проверить. Не создавай файлы отчётов и не заменяй сводку ссылками на них. Blocked/skipped/ошибка инфраструктуры не являются успешной проверкой.
8. Остановись. Не исправляй найденное, не запускай дополнительный review-loop, следующие треки, commit, push или MR. Проверки не дают разрешения на разработку.
